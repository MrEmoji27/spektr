# Packaging spektr for Windows

The point of everything in this folder: someone with no Python, no terminal
habits and no patience can download one file and see their music.

```powershell
# portable exe  ->  dist\spektr.exe
powershell -ExecutionPolicy Bypass -File packaging\build_exe.ps1

# installer     ->  dist\installer\spektr-0.2.0-setup.exe  (needs Inno Setup 6.3+)
powershell -ExecutionPolicy Bypass -File packaging\build_exe.ps1 -Installer
```

The script builds in its own `.venv-build`, so your working environment is
never touched, and it smoke-tests the result with `spektr.exe --version`
before it claims success.

| File | What it is |
|---|---|
| `spektr.spec` | PyInstaller build definition. Onefile by default; `SPEKTR_ONEDIR=1` switches to a folder build |
| `entry.py` | The frozen entry point — forces UTF-8 on the console streams, then calls `spektr.app.main` |
| `build_exe.ps1` | One command: venv, dependencies, build, smoke test, optionally the installer |
| `installer.iss` | Inno Setup script — per-user install, Start Menu shortcuts, optional PATH entry, uninstaller |
| `spektr.ico` | Generated by `make_icon.py`; committed so building needs no Pillow |
| `make_icon.py` | Redraws the icon. Run it only if you want to change the artwork |

CI does the same thing on a clean `windows-latest` runner —
[`.github/workflows/build-windows.yml`](../.github/workflows/build-windows.yml)
builds both artifacts on every `v*` tag and attaches them to the release, so
you never need a Windows machine to cut one. A matching
[`build-linux.yml`](../.github/workflows/build-linux.yml) produces `dist/spektr`,
the native ELF for Linux users, on `ubuntu-latest`.


## Things that are true and worth knowing before you ship it

**It must be a console exe.** spektr is a TUI — Textual draws inside a
terminal. `console=False` produces a binary with nowhere to draw that exits
instantly. Double-clicking the console build opens a black window with the
visualiser in it, which is correct. Tell first-time users that: *"a black
window opens — that's the app, not an error."*

**Size and cold start.** numpy and textual are most of the download, so expect
roughly 60–100 MB. The onefile build unpacks itself into a temp directory on
each launch, which adds a few seconds before the first frame. The onedir build
(and therefore the installer) has nothing to unpack and starts immediately —
that is the whole reason the installer ships the folder version.

**SmartScreen.** Both artifacts are unsigned, so Windows may show
*"Windows protected your PC"* the first time. Options, in ascending order of
effort:

1. Tell people to click **More info → Run anyway**. Free, and normal for
   open-source tools.
2. Ship the installer rather than the portable exe — it accumulates reputation
   faster because it is one stable download per release.
3. Buy an OV or EV code-signing certificate and sign both. This is the only
   thing that actually removes the warning, and it costs real money annually.

**Test on a machine with no Python.** A build that works on the dev box proves
nothing — the failure mode being packaged away is a missing interpreter and
missing DLLs. A fresh VM, or a friend's laptop, is the real test.

## Why the spec looks the way it does

`soundcard` reads `mediafoundation.py.h` from beside its own `__file__` at
import time, so that file has to be inside the bundle. It ships a PyInstaller
hook that says exactly this; the spec collects it a second time in case the
hook's entry point is not picked up.

`sounddevice` finds PortAudio through `_sounddevice_data`, a separate package
whose Windows wheel carries `libportaudio64bit.dll`. That package does not
exist in the Linux wheel, which is why the spec's collection helper treats a
miss as a note rather than an error.

`textual` keeps tree-sitter query files (`*.scm`) next to its modules, so it
needs `collect_all`, not just its submodules.

The Windows version resource is generated from `spektr.__version__` into
`build/` at build time, so the number in the exe's Properties dialog can never
drift from the number in the source.
